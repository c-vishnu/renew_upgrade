# Repository instructions for coding agents

Before changing this project, read `PROJECT_KNOWLEDGE.md` at the repository root.

After every material UI, behavior, API, pricing, architecture, route, command, or data-model change:

1. Update the relevant section of `PROJECT_KNOWLEDGE.md` so it matches the implementation.
2. Add a short dated entry to its **Change log**.
3. Treat documentation updates as part of the requested change, not as optional follow-up work.

Keep the knowledge document concise and factual. Confirm details from the source code rather than preserving stale documentation. Do not record secrets, credentials, machine-specific temporary paths, or generated build artifacts.
